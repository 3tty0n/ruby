* Build from scratch

** CRuby

#+begin_src sh
git checkout 4e51dfefae
./autogen.sh                 # at the repository root
cd rpyyarv
make build-cruby             # --enable-shared, YJIT and ZJIT
make link                    # librpyyarv_boot, used by make test
#+end_src

=build-cruby= configures in =../build= with =--enable-shared= plus
=CRUBY_JIT_CONFIGURE_ARGS= (default =--enable-yjit --enable-zjit=); extra
flags go in =CRUBY_CONFIGURE_ARGS=.  It stops early if =rustc= is missing.

** RPython and its patches

#+begin_src sh
make pypy-patch              # fetches ./pypy at the pinned commit, then patches
make build-interp            # rpyyarv       (default translation options)
make build-jit               # rpyyarv-jit   (-Ojit)
#+end_src

=./pypy= is a shallow fetch of =PYPY_COMMIT= (=4eeb73ca9598=).
=pypy-patch= applies every =pypy-patches/*.patch= that is not already
applied and fails if one does not apply; running it again is a no-op.
=PYPY_PATCH_SKIP=0002= leaves one patch out for the build-only ablations.
Both translations depend on =pypy-patch=, so =make build= does all of this.
On the reference machine the translations take 1 min (=rpyyarv=) and 4 min
(=rpyyarv-jit=).

Apply all four patches on every architecture: that is what the paper's
binaries were built from, and the aarch64-only ones do nothing on x86-64.

| Patch | Files | aarch64 | x86-64 |
|-------+-------+---------+--------|
| 0001 int-ror | =jit/backend/aarch64/*=, plus a backend-only =INT_ROR= resop in =metainterp/resoperation.py= and =executor.py= | peephole that fuses =(x >>u k) \vert (x << 64-k)= into one =ROR= (the flonum codec); also dumps =jit-backend-counts= at exit | applies; inert.  Only the aarch64 regalloc emits =INT_ROR=, and x86 already dumps the counts.  Flonum rotates stay two shifts and an or on x86, a small performance difference, not a correctness one |
| 0002 gc-mark-reads-vables-without-forcing | =jit/metainterp/virtualizable.py=, =rlib/jit.py= | needed | needed: arch-independent |
| 0003 save-callee-saved-vfp-regs | =jit/backend/aarch64/{assembler,registers}.py= | needed: AAPCS64 makes d8-d15 callee-saved and the backend uses d8/d15 as scratch, so C callers (CRuby) lost float values; also passes =supports_floats= through in the cond-call slow path | applies; inert.  SysV x86-64 has no callee-saved XMM register, and the x86 slow path already passes =supports_floats=.  Win64 (xmm6-15 callee-saved) is out of scope |
| 0004 extern-forces-virtualizable-without-random-effects | =jit/codewriter/effectinfo.py=, =rtyper/lltypesystem/rffi.py=, =translator/backendopt/collectanalyze.py= | needed | needed: arch-independent |

The x86-64 backend keeps the jitframe in =rbp= (aarch64: =x29=), saves only
the SysV callee-saved general registers in its prologue, and logs
=jit-backend-addr= in the same format, so the harness's code-size parsing is
unchanged.  Whether the RPyYARV JIT is correct on x86-64 has not been
checked; the verification steps below are the test.

** Benchmarks and gems

#+begin_src sh
make setup                   # ruby-bench and AWFY at pinned commits, gems
#+end_src

=make setup= fetches =ruby-bench= at =RUBY_BENCH_COMMIT= and =awfy= at
=AWFY_COMMIT= (with =scripts/awfy-som-set.patch=), then bundles every
ruby-bench benchmark's =Gemfile.lock= into =.bench-gems= with the CRuby under
test and runs the railsbench database setup.  Bundler 4.0.16 rewrites the
=BUNDLED WITH= and bundler checksum lines of about 25 lockfiles; the gem
versions stay as locked, and the manifest records the checkout as dirty.

Two environment pitfalls:

- =GEM_PATH=: the drivers run on =../build/ruby=, uninstalled.  If the
  default gem path holds a native =json= (or other) gem compiled against a
  different =libruby=, the driver dies loading it.  The reference runs set
  =GEM_PATH= to rbenv's Ruby 4.0.6 gem directory; any directory without such
  gems works (untested beyond that one).
- =AWFY_RUBYLIB=: AWFY needs =set/subclass_compatible.rb= from =../lib=.
  =make= sets it; a hand-run =scripts/bench.rb= without it fails every AWFY
  benchmark, CRuby's too.

** Verification

#+begin_src sh
make test                    # ctypes tests of the boot shim and GC hooks
make eval-test               # the harness's own regression tests
make eval EVAL=doctor        # binaries, checkouts and engines start
make gccheck                 # both binaries vs CRuby, malloc limit 16384
make gccheck GCLIMIT=1024
make compactcheck stresscompactcheck timercompactcheck
make ractorcheck
#+end_src

=gccheck= runs =rpyyarv= and =rpyyarv-jit= from =BIN= (default =.=) on the
=gcscripts= list and compares their output with CRuby's.  =app_lc_fizzbuzz=
is always skipped: it does not run without the GC limit either.  A "crash"
with exit 142 is the 60 s alarm (=GCTIMEOUT=) firing, a timeout rather than
a fault in the VM.

* The campaign

=evaluation/campaign.sh= is the driver the paper's numbers come from.  It
runs one experiment at a time, each behind a quiet-machine gate: the 5-minute
load average must drop below =GATE_LOAD= (3.0), polled every minute, for at
most =GATE_TIMEOUT= (2 h), after which the step runs and the gate log says
=GATE-TIMEOUT ... FLAG=.  It reads the load average from =/proc/loadavg= on
Linux and =sysctl vm.loadavg= on macOS.  A watchdog kills any =rpyyarv=
child older than 15 min (every run has a 600 s alarm, which RPyYARV does not
always honour), and each step reaps leftovers.  =EVAL_OPTIONAL_ENGINES=0=
keeps TruffleRuby and JRuby out, as in the paper.

#+begin_src sh
GEM_PATH=... nohup evaluation/campaign.sh &     # or STEPS="gc nursery"
#+end_src

Logs go to =evaluation/results/campaign-STAMP/= (=campaign.log=,
=gate-log.txt=, =step-NAME.log=); results go to =evaluation/results/= as
usual.  Run it detached (=nohup=): a session-bound background job may be
killed with its terminal.

The steps, in order, and their wall-clock time on the reference machine
(from manifests' =seconds=):

* GC and compaction stresses

Each =gccheck= variant runs the whole =gccheck= suite (both RPyYARV binaries,
output compared with CRuby, =RUBY_GC_MALLOC_LIMIT=16384=).  Stock CRuby is
the reference for (a) and (c): it runs under the same stress, so a script it
cannot survive is skipped as a host problem, not charged to RPyYARV.

| Stress | What it does | Where objects move | gccheck command |
|--------+--------------+--------------------+-----------------|
| (a) auto-compaction | =GC.auto_compact=, every GC major | any allocation inside host C code, e.g. mid method search | =make compactcheck= |
| (b) dispatch compaction | =GC.compact= at one in 4096 RPyYARV dispatches | only at RPyYARV dispatch boundaries | =make stresscompactcheck= |
| (c) timer thread | =GC.verify_compaction_references= every 20 ms from a thread | where the main thread yields (GVL, interrupt checks), e.g. in a delegated call | =make timercompactcheck= |
| (d) dispatch full GC | a full, non-moving GC at one in 4096 dispatches: everything RPyYARV holds must be marked | nothing moves; unmarked objects are freed | =make gccheck GCENV='RPYYARV_GC_STRESS=1 RPYYARV_GC_STRESS_EVERY=4096'= |

(b) and (d) set =RPYYARV_GC_STRESS= (=compact= or =1=) and
=RPYYARV_GC_STRESS_EVERY=; CRuby has no equivalent, so its reference output
is unstressed.  (a) loads =test/autocompact.rb= and (c)
=test/compact_prelude.rb= through =RUBYOPT=.

The same four stresses (and =none=) run over the benchmark corpus with
=EVAL=stress= (=evaluation/stress.rb=: one verified process per benchmark,
stress and engine; =stress.csv= and =stress-summary.csv=) and over ruby/spec
with =evaluation/spec.rb --env K=V=, which passes each variable to mspec and
the engine under test.  =RPYYARV_GC_STRESS=1= at every dispatch (the
=gc-stress= ablation) is orders of magnitude slower and is not in the
default ablation set.

* Memory

- =EVAL=memory= (=evaluation/memory.rb=): peak RSS per engine and benchmark
  through =/usr/bin/time= (=-l= on macOS, =-v= on Linux), the host heap from
  =GC.stat=, the RPython heap and JIT code size from =PYPYLOG=
  (=gc-minor,gc-collect-done,jit-backend-addr=).  =evaluation/membreak.rb
  RESULTS/memory.json= splits each peak into host heap, framework heap, JIT
  code and remainder.
- =evaluation/footprint.rb= (macOS only): the end-of-run physical footprint
  split into components that sum to it, from =vmmap -wide= of the process at
  exit (=footprint_prelude.rb=), with the host's and RPython's own accounts
  carving the malloc and VM regions.  The paper's runs:

  #+begin_src sh
  nice -n 19 ruby evaluation/footprint.rb --out DIR --suite all
  nice -n 19 ruby evaluation/footprint.rb --out FOCUS \
    --filter deltablue --filter richards --filter hexapdf --filter lobsters \
    --filter optcarrot --filter railsbench --filter rubocop \
    --msl deltablue --msl richards --msl hexapdf --msl lobsters \
    --msl optcarrot --msl railsbench --msl rubocop \
    --dump deltablue --dump lobsters --dump optcarrot --dump railsbench \
    --dump richards --dump rubocop
  ruby evaluation/footprint.rb --report DIR/footprint.jsonl
  #+end_src

  =--msl= reruns under =MallocStackLogging=lite= and classifies live
  mallocs with =malloc_history=; =--dump= writes a heap dump after a full GC
  (=RPYYARV_COVERAGE=1= under rpyyarv-jit).  Like every script here it
  derives the child environment from the checkout, as =scripts/bench.rb=
  does.  One measured process at a time, niced; the full suite takes
  several hours.
- =evaluation/retention.rb HEAP.json [COVERAGE_OUTPUT] [--json]=: which host
  objects stay alive only because RPyYARV roots them, from a =--dump= heap
  dump and the coverage output's root inventory.
- =evaluation/immobile.rb --out DIR [--suite ...]=: objects a compaction
  had to leave in place, and heap density afterwards.

* Time breakdown

=evaluation/breakdown.rb= (macOS only) samples =rpyyarv-jit= with =sample=
(1 ms, main thread) and puts every stack into one bucket: CRuby or RPython
GC, compile, delegated CRuby, compiled trace, or interpreter.  JIT code is
"<unknown binary>" in =sample='s stacks and is split into loops and bridges
by the =jit-backend-addr= address ranges.

#+begin_src sh
ruby evaluation/breakdown.rb --out DIR --procs 3 --window 15 \
  --filter railsbench --filter lobsters --filter shipit --filter rubocop \
  --filter hexapdf --filter keyword_args                  # steady state
ruby evaluation/breakdown.rb --out DIR --phase warmup ...  # launch to WARMED
ruby evaluation/breakdown.rb --out DIR --sends ITERS ...  # sends per iteration
ruby evaluation/breakdown.rb --report DIR/breakdown.jsonl [--phase warmup]
#+end_src

* Correlations, figures, reports

- =ruby evaluation/correlations.rb MECHANISMS-DIR ...=: Pearson and Spearman

  95% CIs; writes =DIR/correlations.csv=.
- =make eval EVAL=figures EVALFLAGS="DIR ... [--out D]"=: every paper figure
  from the given results directories (the last one of each kind; all
  ablation directories are merged).  SVG always; PDF at 72 dpi when
  =rsvg-convert= is found (Homebrew's, else the first on =PATH=).

Which paper results reproduce where:

- As-is on Linux/x86-64 (in principle; untested): everything in the
  campaign (performance, warm-up, boundary, crossing, coverage, delegation,
  mechanisms, correlations, =EVAL=memory= peak RSS, gc, nursery, ablations,
  stress, spec stress), the =gccheck= stresses, figures, loc and retention
  (=footprint.rb --dump= does not need vmmap).  Absolute numbers differ by
  machine; the patches make the x86 JIT differ in one known way (no fused

on the x86 backend (=make test=, =gccheck= and the stresses answer that);
whether =stacklet= fibers and the embedded CRuby's own coroutines coexist
there as on arm64; the real symbol names in =perf= output; and whether
=RUBY_GC_MALLOC_LIMIT=16384= fires as many collections on glibc malloc.

* Choice of harness

The experiment controller is Ruby because the existing AWFY and ruby-bench
adapters are Ruby programs.  It adds no gem dependency.  ReBench remains useful
for a conventional AWFY steady-state replication, but it is not the primary
controller: =scripts/bench.rb= rejects silently delegated runs and handles the
RPyYARV-specific gem protocol.

The controller never builds or modifies the VM.  Every run gets a new results
directory containing the exact command, environment, git commit, dirty paths,
host description, logs, and machine-readable data.  This makes it safe to stage
experiments while implementation work is happening in the same checkout.

=make eval EVAL=<command> EVALFLAGS="..."= runs any of these with the
build tree's Ruby and the benchmark environment already set.  The paper-side
plan for each item is =docs/evaluation-plan.org=.

Run =make eval= first: its doctor checks that both benchmark checkouts and all
required engines are present and can start.  Run =make eval-test= for the
controller's artifact-analysis and plotting regression tests.

=performance= produces =measurements.csv=, =ratios.csv=, =comparisons.csv=,
and =summary.csv= from the raw output.  CRuby, YJIT, and ZJIT are always
requested.  AWFY and ruby-bench remain separate rows in =summary.csv= before
the overall result.

** Optional engines

TruffleRuby and JRuby are added when they are found in =PATH=, or through
=TRUFFLERUBY_BIN= / =GRAALVM_HOME= and =JRUBY_BIN= / =JRUBY_HOME=.  Installed
rbenv and asdf versions are also searched, and each executable must pass a
startup probe.  =EVAL_OPTIONAL_ENGINES=0= disables the search, so a rerun of
a protocol that had no optional engine does not gain one.

** Warm-up

The raw file retains every process's complete iteration sequence and the
harness warm-up boundary.  =warmup.csv= reports the first five-iteration window
within 10% of the steady median and its cumulative time.

Each process is also classified in the style of Barrett et al., "Virtual
Machine Warmup Blows Hot and Cold" (OOPSLA 2017), from that same stable
iteration: /flat/ when it is iteration 0, /no steady state/ when no such
window exists in the run, and otherwise /warmup/ or /slowdown/ according to
whether the median of the iterations before it is above or below the steady
median.  The classifier is deliberately cruder than Barrett's changepoint
analysis: it uses one threshold and reports no confidence interval, so it
separates the four shapes but does not certify a process as truly steady.
=warmup-summary.csv= aggregates the classification and the stable iteration
and time-to-stable distributions per engine and per suite and engine, and
=warmup-comparison.csv= puts the per-benchmark medians of =rpyyarv-jit= and
=cruby+yjit= side by side with their ratio.  =run.rb warmup DIR= recomputes
all three from an existing =raw.json= without rerunning any benchmark.

** Ablations and plots

VALUE-direct ablations use the existing extra-engine protocol.  A variant
binary passed as =--engine NAME=PATH= is added to =comparisons.csv= and gets
its own ratio and scatter plots; the VM under active development needs no
evaluation-only switch.  The build-only ablations (=PYPY_PATCH_SKIP=0002=,
=0004=) need their own =make build-jit=; =EVAL=ablate= prints the recipes.

Successful performance runs produce publication-ready SVG files:

- =ratio-to-ENGINE.svg=: benchmark on the x axis and RPyYARV/reference time on
  a log-scaled y axis.  The 1x reference line separates wins from losses.
- =scatter-ENGINE.svg=: reference time versus RPyYARV JIT time on equal log
  scales.  Points below the diagonal are RPyYARV wins.

* Evaluation matrix

| Claim | Experiment | Current collector | Required extension |
|-------+------------+-------------------+--------------------|
| End-to-end performance | Detected engines, 82 benchmarks | =performance= | Freeze machine and repetitions |
| VALUE-direct causality | Fast path versus residual call | =ablate= plus binary variants | A fast-path env switch |
| Delegation boundary | sends and dominant callees | =boundary=, =crossing= | time in CRuby and trampolines |
| Compatibility | native/delegated/failure coverage | =coverage= | reviewed structural/engineering classification |
| Native versus delegated | one binary, RPYYARV_NO_REQUIRE | =delegation= | — |
| Implementation effort | categorized physical LoC | =loc= | reviewed line-level taxonomy |
| GC integration | malloc limits and nursery sizes | =gc=, =nursery=, =stress= | root-marking time needs a VM counter |
| Fiber integration | micro plus optcarrot | artifact schema only | stack-window switch |
| Warm-up | iteration curves and JIT events | =performance= raw samples | case-study curves |

| Mechanism | four representative cases | =mechanisms= | live code size |

The =mechanisms= command now collects the trace/guard, boundary, YJIT, and ZJIT
statistics.  It emits =mechanisms.json=, =mechanisms.csv=, one raw RPython JIT
diagnostic log per benchmark, and three causal-diagnostic plots when a
performance raw file is provided.  These instrumented runs are never used as
performance numbers.

* Rules for causal experiments

Each ablation must change one named mechanism, use the same source commit where
possible, and store its build identity in the manifest.  Instrumented boundary
or JIT-log runs are never mixed with timing runs.  A result is excluded only by
a recorded rule; delegation and failure remain explicit outcomes rather than
silently disappearing from a geometric mean.

The LoC report is deliberately conservative.  It counts tracked physical lines
and assigns whole files by first match.  It is reproducible but not the final
paper number until mixed-purpose files have a reviewed line-level classification.
